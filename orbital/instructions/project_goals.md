# Project Goals — Kimi PM 作业: Orbital Team Feature 规划

## Mission
为面试 Kimi 产品经理岗位产出一份作业 repo：针对「Orbital 与 Claude Code / Codex 定位雷同」的问题，规划 Orbital 的 Team Feature 产品方向。交付物 = 完整产品规划文档（README 电梯陈述、竞品分析、用户场景、PRD、路线图）+ 可演示 demo，整理成 repo 提交给 Kimi。

## Triggers
- 用户消息为主渠道，无定时任务。
- 若用户给出明确 deadline，可设置提醒/trigger。

## Scope
- **In**: 竞品研究（Claude Code / Codex / Cursor 等）；Orbital 现状梳理（GitHub repo + 一手运行体感）；目标用户与场景分析；PRD 与路线图；demo（后置）；GitHub repo 搭建与推送。
- **Out**: 不修改 Orbital 官方仓库；不做与作业无关的工作；**demo 在基础文档沉淀完成并获得用户确认前不动工**（用户明确指示）。

## Rules
- 语言：文档中文为主，术语与 repo 名用英文。
- 作业独特优势：本项目本身就运行在 Orbital 内（管理 agent + 多子 agent 编排 + 持久记忆机制），论据优先用一手体感 + 源码/官方文档，避免臆测。
- 竞品信息必须联网核实（知识可能过时），标注信息来源与日期。
- 用户交付物放 `docs/` / `deliverables/`，不写入 `orbital/` 系统目录。
- 研究性理解写成 markdown 沉淀到工作区，并登记进 INDEX.md。

## Preferences
- 用户用中文交流，节奏偏快，倾向自主推进、少问多干。
- 决策点（如 repo 命名、demo 形态）先给出建议默认值再执行。
